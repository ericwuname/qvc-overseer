## 二、技术变更详情

### 2.1 第50条规则: django_sql_injection

**文件**: `qvc/rules/python/django_sql_injection.py`

**检测模式**:
- `Model.objects.raw(f"...{var}...")` — f-string注入
- `Model.objects.extra(where=[...])` — extra条件注入
- `RawSQL(f"...{var}...")` — RawSQL注入
- 也检测 `.format()` 和 `%` 格式化注入

**规则层级**: PATTERN（置信度92%）

### 2.2 Python AST语义分析器

**文件**: `qvc/analyzers/ast_analyzer.py`

**核心能力**:
- 导入解析：识别`from app.xxx import yyy`的合法性（检查`__init__.py`）
- 函数提取：函数名、参数、装饰器、async标记
- 类提取：类名、方法列表、基类
- 作用域树：全局变量、函数内局部变量
- 短路检测：`if x and x.method()` 模式识别
- 调用图构建

**集成方式**: StaticAnalyzer.analyze_file() 在Python文件上自动调用ASTAnalyzer，结果通过 `ast_context` 参数传给规则。规则可选择使用（向后兼容）。

### 2.3 GitHub Actions自动PR

**文件**: `qvc/task_pool/auto_pr.py`

**工作流**:
```
代码push → QVC扫描 → 提取≥90%置信度bug → 生成PR内容 → 创建PR
```

**安全设计**: QVC绝不自动修改代码。PR仅包含修复建议描述，由开发者/AI Agent手动修复。

**PR格式**:
- 标题: `[QVC] Found N fatal/severe bugs — external review`
- 正文: 严重度分类表 + 逐条详情 + 修复建议 + 盲区标注

### 2.4 VS Code扩展发布就绪

**目录**: `vscode-extension/`

**变更**:
- 版本号: 0.6.0 → 1.0.0
- 补充Marketplace元数据: publisher, icon, galleryBanner, keywords, license
- 命令: Full Scan, Scan Changed Files, Fix Tasks, Show Status
- 右键菜单: 文件夹/编辑器上下文集成

## 八、经验总结

1. **承诺驱动开发有效**: 锁定范围到"只做承诺过但未兑现的"，天然防蔓延
2. **AST分析不是银弹**: 它有帮助，但真正价值在规则质量，不在解析器
3. **自检不可跳过**: 每个版本都找到了自己的问题；V8第一次实现0真实bug
4. **防蔓延铁律和做功能同等重要**: 说"不"的次数决定了交付的质量
