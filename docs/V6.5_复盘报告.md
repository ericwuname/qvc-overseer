## 二、成功模式

### 模式 1: 双语文档降低国际门槛
V6.5 的 README 有了双语入口，英文用户首次看到项目不会因为中文文档而关掉。这是从"个人仓库"到"国际项目"的关键一步。

### 模式 2: 规则扩展有序分层
29 条新规则按语言分组、按置信度分层（CERTIFICATE > PATTERN > HEURISTIC），没有出现 V1 的"281 条全标致命"问题。

### 模式 3: 自检闭环
QVC 扫描自身发现 BOM 问题并修复。吃自己的狗粮始终是最有效的质量保证。

## 三、问题与根因

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | 规则文件自引误报（os_system.py 检测到自己的字符串字面量） | 规则源码包含被检测模式 | 标记为已知误报，后续考虑规则源码目录排除 |
| 2 | class 名 double Rule 后缀 | 模板 `{cls}Rule` 中 cls 已含 Rule | 正则修复，后续模板需去重 |
| 3 | register_many 列表缩进错乱 | 字符串插入未保留上下文缩进 | 精确定位插入点修复 |

## 四、关键教训

1. **规则文件包含被检测的字符串模式是正常现象**，不应视为 bug——但需要标记说明
2. **代码生成模板必须验证输出**——class 名 double 后缀的问题出现了两次
3. **国际化不是翻译完就完了**——README 双语入口、CONTRIBUTING 国际化指南同等重要
