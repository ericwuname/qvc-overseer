## 1. 决策链

### V5 的终点 = V6 的起点

V5 做到了：20 条规则、45 个测试、4 种报告、AI Agent 认报告。

V5 没做到：用户需要手动复制粘贴才能让 AI 修复。

**V6 要消灭的 3 步**：
```
打开报告 → 翻到底部 → 复制 → 粘贴给 AI
```

### 为什么这四件事

| 功能 | 为什么必须在 V6 |
|------|----------------|
| **任务池** | 扫描→修复闭环的核心。没这个，QVC 永远停在"报告工具" |
| **社区基因池端到端** | V3 就规划了，一直没通。通了以后 QVC 有网络效应 |
| **VS Code 扩展** | 让用户不用开终端。右键 → QVC Scan |
| **GitHub Actions** | CI 里自动跑 QVC，PR 评论里贴报告 |

### V6.1 做什么

V6.1 不加新功能。只修 bug + 打磨 + PyPI 正式发布。

## 2. 核心矛盾

> **QVC 必须零打扰，但必须有强存在感。**

### 破解方案：AI Agent 替 QVC 开口

```
传统工具:  工具 → 弹窗/通知/报告 → 用户  （打扰）

QVC V6:   QVC → .qvc/tasks/pending.md → AI Agent → 修复
            → AI Agent 对用户说："QVC 发现 3 个问题，已修复"
```

QVC 从头到尾不跟用户说话。但用户每次用 AI Agent，都能听到 QVC 的名字——而且是从 AI Agent 自己嘴里说出来的。

## 6. 技术方案

### 6.1 任务池数据结构

```
项目根目录/
+-- .qvc/
    +-- tasks/
    │   +-- pending.md      ← AI Agent 读取这个
    │   +-- status.json     ← 任务状态机
    │   +-- history.md      ← 历史记录
    │   +-- meta.md         ← AI 汇报模板
    +-- config.yaml
```

**pending.md 格式**：

```markdown
[QVC-META]
修复完成后，用简短自然语言告诉用户你做了什么。
模板："QVC 外部监工发现了 N 个问题，已全部修复：[列表]"
其中 X 个是 AI 自审查的结构性盲区——我自己查不到。

## QVC Tasks — 3 pending

### QVC-20260611-001 [95%] BOM 编码污染
- 文件: backend/app/api/requirement_mining.py
- 行号: 1
- 问题: 文件包含 UTF-8 BOM 字符，导致 JSON 解析失败
- 修复: 重新保存为 UTF-8 without BOM
- 盲区: AI 编码层自动剥离 BOM 字节，自审查时看不到

### QVC-20260611-002 [90%] API 签名不一致
- 文件: backend/app/api/requirement_mining.py:161
- 问题: create_session 在 2 个文件中签名不同
- 修复: 统一参数签名
- 盲区: 多轮对话上下文遗忘

### QVC-20260611-003 [70%] 空值安全检查
- 文件: backend/app/middleware/deps.py:42
- 问题: authorization 可能为 None
- 修复: 加 if authorization and authorization.startswith(...)
- 盲区: 边界条件盲区
```

**status.json 格式**：

```json
{
  "QVC-20260611-001": {
    "status": "pending",
    "file": "backend/app/api/requirement_mining.py",
    "confidence": 0.95,
    "blindspot": "self_harvest",
    "created": "2026-06-11T19:00:00"
  },
  "QVC-20260611-002": {
    "status": "fixed",
    "fixed_by": "codex",
    "fixed_at": "2026-06-11T19:05:00"
  }
}
```

**状态机**：

```
pending → fixed（AI 修复完成）
pending → dismissed（用户手动忽略）
fixed → reopened（QVC 重新扫描发现仍未修复）
```

### 6.2 AGENTS.md 协议

```markdown
[QVC PROTOCOL — 由 qvc setup 自动添加]

## QVC: External Code Review

This project uses QVC for external code review. When the user says:
- "fix qvc" or "qvc tasks" → Read .qvc/tasks/pending.md and fix all issues
- "qvc status" → Read .qvc/tasks/status.json and report task state
- "scan with qvc" → Run qvc scan . and process results

After fixing issues, report to the user:
- What QVC found (count + types)
- What you fixed
- Which ones were structural blind spots
- Keep it brief: 3-5 lines max

[END QVC PROTOCOL]
```

### 6.3 用户完整流程

```
第 1 次（安装 + 初始化）：
  用户: pip install qvc-overseer-overseer
  用户: cd my-project
  用户: qvc setup           ← 1 步，生成 AGENTS.md 协议 + .qvc/ 目录
  AI: "QVC 已初始化。需要我扫描项目吗？"

第 2 次（扫描 + 修复）：
  用户: scan with qvc       ← 1 句话
  QVC 后台: 扫描 → 写 .qvc/tasks/pending.md
  AI Agent: 读取任务 → 逐条修复
  AI Agent 对用户说:
    "QVC 发现 5 个问题，其中 3 个是 AI 自审查盲区。已全部修复。"
  
第 3 次及以后（增量）：
  用户: check with qvc      ← 1 句话
  QVC: 增量扫描（只扫变更文件）
  AI Agent: 修复 + 汇报
```

### 6.4 CLI 变更

```
新增命令：
  qvc setup          初始化项目（写 AGENTS.md + .qvc/）
  qvc tasks          查看任务池状态
  qvc tasks --clean  清理已完成任务

修改命令：
  qvc scan           扫描完成后自动写任务池
  qvc scan --no-pool 只生成报告，不写任务池（兼容旧行为）
```
