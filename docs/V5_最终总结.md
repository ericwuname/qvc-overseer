## 一、V5 做了什么

### 1.1 核心规则（2 条新增，总计 20 条）

| 规则 | 做什么 | 为什么重要 |
|------|--------|-----------|
| API_DRIFT | 同名函数在不同文件签名不一致 | 证明 AI Agent 多轮对话后遗忘接口约定 |
| STALE_REFERENCE | 引用了已删除/已重命名的符号 | 证明 AI Agent 不知道项目其他部分变了 |

这两条规则拼出了 GENERATION_ORDER 的 80% 价值——不需要额外做"生成时序分析"，跨文件一致性检测天然覆盖了。

### 1.2 感知层（3 项）

| 功能 | 做什么 |
|------|--------|
| AHA 时刻 | 扫描完告诉用户"这 3 个 bug 你的 AI 绝对看不见，因为……" |
| 传播钩子 | 报告底部一键分享文案（不提 QVC 品牌名） |
| Mode B 默认 | 不传自审报告也能看到行业基准漏报率 |

### 1.3 基础设施（2 项）

| 功能 | 做什么 |
|------|--------|
| 进度条 | 大项目不卡住，实时反馈扫描进度 |
| 回归测试 11→45 | 新规则不引入回归 |

### 1.4 AI 修复指令（V5 末期追加）

| 功能 | 做什么 |
|------|--------|
| AIFixPromptGenerator | 报告底部插入 AI 可消费的修复任务块 |
| --fix-prompt | 终端直接输出可复制修复指令 |
| qvc fix | 独立生成修复指令文件 |

## 五、V5 的最大教训

**"发现→修复"之间差了 3 步手工操作。**

QVC 能找到真 bug。用户认。但用户需要：打开报告 → 翻到底部 → 复制 → 粘贴给 AI → 修复 → 再扫。

V6 的唯一使命：**把 3 步压成 1 句话。**
